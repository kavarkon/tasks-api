# Общие правила

- Регистрация не выполняет вход. Повтор пароля проверяется на фронтенде и не отправляется в API.
- После входа JWT хранится в `HttpOnly` cookie `access_token`. В production cookie также имеет `Secure` и `SameSite=Lax`.
- Все операции с pack-ами и задачами доступны только авторизованному пользователю и только для его ресурсов.
- `title` pack-а и задачи обязателен, не может состоять только из пробелов и не может быть длиннее 255 символов.
- Обновление через `PUT` передаёт все поля запроса, а не только изменённые.
- Примеры ниже предполагают, что для запросов на изменение передан действительный CSRF-токен.

# Формат ошибки

Общая ошибка сохраняет текущие поля `status`, `message`, `path`:

```json
{
  "status": 404,
  "message": "Pack with id 42 was not found",
  "path": "/api/packs/42"
}
```

Для ошибок валидации дополнительно возвращается `fields`, чтобы фронтенд мог показать ошибки под полями:

```json
{
  "status": 400,
  "message": "Проверьте введённые данные",
  "path": "/api/auth/register",
  "fields": {
    "email": "Некорректный адрес электронной почты",
    "password": "Пароль обязателен"
  }
}
```

# CSRF

## 1 Получение токена

`GET /api/auth/csrf` — доступен без входа.

Ответ: `200 OK`, CSRF cookie и токен для заголовка:

```json
{
  "headerName": "X-CSRF-TOKEN",
  "token": "csrf-token"
}
```

Фронтенд отправляет cookie и указанный заголовок для `POST`, `PUT`, `PATCH`, `DELETE`, в том числе для регистрации, входа и выхода. После входа и выхода фронтенд запрашивает актуальный CSRF-токен заново.

## 2 Отсутствующий или неверный токен

Запрос на изменение без действительного CSRF-токена: `403 Forbidden`. Операция не выполняется.

# Регистрация

## 1 Успешная регистрация

`POST /api/auth/register`

Запрос:

```json
{ "email": "user@example.com", "password": "example-password" }
```

Ответ: `201 Created`.

```json
{ "id": 1, "email": "user@example.com" }
```

## 2 Некорректные поля

Пустой или некорректный email либо пароль, не соответствующий ограничениям: `400 Bad Request`, ошибки полей возвращаются в `fields`.

## 3 Email уже зарегистрирован

Регистрация с уже занятым адресом, в том числе отличающимся только регистром: `409 Conflict`. Ответ содержит общее сообщение и ошибку поля `email`. Уникальность также проверяется ограничением БД.

# Вход и выход

## 1 Успешный вход

`POST /api/auth/login`

Запрос:

```json
{ "email": "user@example.com", "password": "example-password" }
```

Ответ: `200 OK`, cookie `access_token` и данные пользователя без пароля и токена:

```json
{ "id": 1, "email": "user@example.com" }
```

## 2 Ошибка входа

- Неверная почта или пароль: `401 Unauthorized` и одинаковое сообщение «Неверная почта или пароль».
- Некорректные или отсутствующие поля: `400 Bad Request`, ошибки возвращаются в `fields`.

## 3 Текущий пользователь

`GET /api/auth/me` с действительной cookie.

Ответ: `200 OK`.

```json
{ "id": 1, "email": "user@example.com" }
```

## 4 Выход

`POST /api/auth/logout` очищает cookie и возвращает `204 No Content`. Повторный выход также успешен. Скопированный JWT остаётся действительным до истечения его срока.

## 5 Нет авторизации

Запрос защищённого ресурса без cookie, с повреждённым или просроченным JWT: `401 Unauthorized`. Для изменяющего запроса также требуется действительный CSRF-токен.

# Pack-и

## 1 Список своих pack-ов

`GET /api/packs`

Ответ: `200 OK`. У другого пользователя этот pack в списке не появится.

```json
[{ "id": 1, "title": "Учёба" }]
```

Если pack-ов нет, возвращается `[]`.

## 2 Свой pack с задачами

`GET /api/packs/1`

Ответ: `200 OK`. Задачи принадлежат только этому pack-у и отсортированы по ID по возрастанию: новые ниже.

```json
{
  "id": 1,
  "title": "Учёба",
  "tasks": [
    { "id": 10, "title": "Прочитать главу", "completed": false, "packId": 1 }
  ]
}
```

Если задач нет, `tasks` — пустой массив.

## 3 Создание pack-а

`POST /api/packs`

Запрос:

```json
{ "title": "Учёба" }
```

Ответ: `201 Created`, `Location: /api/packs/1`.

```json
{ "id": 1, "title": "Учёба" }
```

Владелец определяется по авторизации, а не по данным запроса.

## 4 Изменение pack-а

`PUT /api/packs/1`

Запрос:

```json
{ "title": "Учёба и практика" }
```

Ответ: `200 OK`.

```json
{ "id": 1, "title": "Учёба и практика" }
```

## 5 Удаление pack-а

`DELETE /api/packs/1` — `204 No Content`. Задачи этого pack-а также удаляются.

## 6 Ошибки pack-а

- Свой pack не найден либо указанный pack принадлежит другому пользователю: `404 Not Found` при получении, изменении или удалении.
- Пустой, отсутствующий или слишком длинный `title` при создании или изменении: `400 Bad Request` с ошибкой поля.

# Задачи

## 1 Список своих задач

`GET /api/tasks`

Ответ: `200 OK`. Задачи других пользователей не возвращаются.

```json
[{ "id": 10, "title": "Прочитать главу", "completed": false, "packId": 1 }]
```

Если задач нет, возвращается `[]`.

## 2 Получение своей задачи

`GET /api/tasks/10`

Ответ: `200 OK`.

```json
{ "id": 10, "title": "Прочитать главу", "completed": false, "packId": 1 }
```

## 3 Создание задачи

`POST /api/tasks`

Запрос:

```json
{ "title": "Прочитать главу", "completed": false, "packId": 1 }
```

Ответ: `201 Created`, `Location: /api/tasks/10`.

```json
{ "id": 10, "title": "Прочитать главу", "completed": false, "packId": 1 }
```

Указанный `packId` должен принадлежать текущему пользователю.

## 4 Изменение задачи

`PUT /api/tasks/10`

Запрос:

```json
{ "title": "Прочитать главу", "completed": true, "packId": 1 }
```

Ответ: `200 OK` с обновлённой задачей. При изменении `packId` целевой pack также должен принадлежать текущему пользователю.

## 5 Удаление задачи

`DELETE /api/tasks/10` — `204 No Content`.

## Ошибки задачи

- Задача отсутствует или принадлежит другому пользователю: `404 Not Found` при получении, изменении или удалении.
- Целевой pack отсутствует или принадлежит другому пользователю: `404 Not Found` при создании или изменении задачи.
- Пустой, отсутствующий или слишком длинный `title`, отсутствующие `completed` или `packId`: `400 Bad Request` с ошибками полей.

## Другие ошибки запроса

- Нечисловой или выходящий за диапазон `id` в пути: `400 Bad Request`.
- Некорректный JSON или тип поля: `400 Bad Request`.
- Неожиданная ошибка сервера: `500 Internal Server Error` без технических деталей в ответе.
