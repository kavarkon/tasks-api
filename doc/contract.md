# Контракт Tasks API

Базовый адрес: `https://todo.puorp.ru/api`. Пути эндпоинтов ниже указаны относительно `/api`. Для запроса с JSON-телом используйте `Content-Type: application/json`.

## Эндпоинты

В колонке запроса поля JSON перечислены в фигурных скобках. Все они обязательны и не допускают `null`. `PUT` принимает полный набор полей, частичного обновления нет. Ответ `204` не содержит тела.

| Метод и путь | Тело или параметры URL | Успешный ответ |
|---|---|---|
| `POST /auth/register` | `{email, password}` | `201`, `User`, без входа |
| `POST /auth/login` | `{email, password}` | `200`, `User` и cookie `access_token` |
| `POST /auth/logout` | Без тела | `204`, очищает только cookie `access_token` |
| `GET /packs` | `limit`, `afterId` | `200`, `Page<Pack>` |
| `GET /packs/{id}` | Без тела | `200`, `Pack` |
| `POST /packs` | `{title}` | `201`, `Pack` и `Location: /api/packs/{id}` |
| `PUT /packs/{id}` | `{title}` | `200`, обновлённая пачка `Pack` |
| `DELETE /packs/{id}` | Без тела | `204`, удаляет пачку вместе с её задачами |
| `GET /tasks` | `limit`, `afterId`, `packId` | `200`, `Page<Task>` |
| `GET /tasks/{id}` | Без тела | `200`, `Task` |
| `POST /tasks` | `{title, completed, packId}` | `201`, `Task` и `Location: /api/tasks/{id}` |
| `PUT /tasks/{id}` | `{title, completed, packId}` | `200`, обновлённая задача `Task` |
| `DELETE /tasks/{id}` | Без тела | `204` |

## Форматы данных

* `User`: `{"id":1,"email":"user@example.com"}`.
* `Pack`: `{"id":4,"title":"Учёба"}`. Задачи в ответ не вложены.
* `Task`: `{"id":10,"title":"Прочитать главу","completed":false,"packId":4}`.
* `Page<T>`: объект с массивом `items` из записей типа `T` и полем `nextAfterId` (целое число или `null`).

## Поля запроса

Длина в символах считается в единицах UTF-16, как `length` у строки в JavaScript.

* `email`: строка с корректным адресом до 255 символов. При регистрации и входе API удаляет пробелы по краям и приводит адрес к нижнему регистру до проверки. В ответе адрес в том же виде.
* `password`: непустая строка, не только из пробелов. При регистрации минимум 8 символов и максимум 72 байта в UTF-8, иначе `400` с `fields.password`. При входе превышение 72 байт при прочих корректных данных даёт `401`. Поля подтверждения пароля нет.
* `title`: непустая строка до 255 символов, не только из пробелов.
* `completed`: логическое значение `true` или `false`, не строка. Без этого поля или при `null` ответ `400` с `fields.completed`.
* `{id}` в пути и `packId` в JSON обозначают 32-битные целые числа. В JSON передавайте число без кавычек. Без `packId` или при `"packId": null` в теле задачи ответ `400` с `fields.packId`.

## Доступ

Маршруты `/auth` из таблицы доступны без входа. Для пачек и задач нужен JWT в cookie `access_token` (`HttpOnly`, `SameSite=Lax`, `Secure` только в `prod`). Владелец определяется по cookie, клиент не передаёт его ID. Можно читать и изменять только свои ресурсы, в том числе при выборе пачки для задачи.

Выход очищает только cookie `access_token` и возвращает `204`, в том числе при повторном запросе без cookie входа. Выход не отзывает копию JWT: она действительна до истечения срока токена.

## Пагинация и фильтр задач

| Параметр URL | Для каких списков | Допустимые значения | Если не передан |
|---|---|---|---|
| `limit` | `/packs`, `/tasks` | Целое от 1 до 100 | Лимит 50 |
| `afterId` | `/packs`, `/tasks` | Целое от 1 до 2147483647 | Первая страница |
| `packId` | Только `/tasks` | Целое от 1 до 2147483647 | Задачи из всех своих пачек |

Записи идут по возрастанию `id`. Если есть продолжение, `nextAfterId` равен ID последней выданной записи. Передайте его как `afterId`, сохранив фильтр: вернутся только записи с `id > afterId`. На последней странице `nextAfterId` равен `null`, даже если страница полна. Пустая страница: `{"items":[],"nextAfterId":null}`.

Если параметр передан, пустое значение, пробелы, нецелое значение или число вне диапазона дают `400`. Фильтр `?packId=-1` даёт `400`, а `"packId": -1` в остальном корректном теле задачи даёт `404`: пачка с таким ID не найдена.

## Ошибки

Ошибка API содержит целое `status`, строки `message` и `path`. Необязательный объект `fields` сопоставляет имена полей сообщениям об ошибках. Например:

```json
{"status":400,"message":"Проверьте введённые данные","path":"/api/auth/register","fields":{"password":"Пароль обязателен"}}
```

| Статус | Когда возвращается |
|---|---|
| `400` | При нарушении ограничений полей тела есть `fields`. При неверном JSON, типе поля, параметре списка или неверном формате 32-битного `id` в пути `fields` нет. |
| `401` | Неверные данные входа («Неверная почта или пароль») либо на защищённом маршруте отсутствует, повреждён или просрочен JWT. |
| `403` | Запрос запрещён правилами доступа или CORS. |
| `404` | Запрошенная пачка или задача не найдена либо принадлежит другому пользователю. Это относится и к целевой пачке при записи задачи или фильтрации списка. |
| `405` | После проверки доступа маршрут не поддерживает метод запроса. Заголовок `Allow` перечисляет поддерживаемые методы. |
| `409` | При регистрации нормализованный email уже занят. В ответе есть `fields.email`. |
| `415` | Не поддерживается `Content-Type` тела запроса. |
| `500` | Внутренняя ошибка без технических подробностей. |
